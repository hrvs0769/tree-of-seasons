# 02 · 时间轴、章节与镜头

> 本文解决：故事时间怎么走、14 个章节与画面如何对应、镜头关键帧在哪里，以及改时长/改章节时必须同步哪些地方。
> 主文档见 [`../DEVELOPMENT.md`](../DEVELOPMENT.md)。

## 1. 三个时间量

| 量 | 公式 | 含义 |
|---|---|---|
| `t` | 当前 `storyTime` | 故事时间（秒）；`?t0=N` 可整体偏移 |
| `g` | `growthAt(t)` | 生长进度 0..1，分段平滑；不是 `t/120` |
| `p` | `storySeason(t)` 取小数部分 | 一年进度 0..1，一年 = `SEASON_SECONDS * 4` |

### 1.1 `growthAt(t)`

源码：`src/main.js` 的 `GROW_KEYS` 与 `growthAt()`。

当前关键帧：

```js
[
  [0, 0.000],
  [16, 0.004],   // 种子吸水
  [32, 0.020],   // 破壳
  [56, 0.060],   // 主根向下、主干开始
  [76, 0.140],   // 破土、子叶
  [94, 0.280],   // 幼苗
  [108, 0.500],  // 小树
  [116, 0.750],  // 树冠展开
  [120, 1.000],  // 大树
]
```

每段内部用 `smoothstep(0, 1, u)` 平滑连接。这样前 76 秒（种子/春雨/扎根/破土）占足时间，后面抽枝成树加速。

### 1.2 `storySeason(t)`

```js
if (t < GROW_END) return 0.02 + (0.25 - 0.02) * (t / GROW_END);
return 0.25 + (t - GROW_END) / (SEASON_SECONDS * 4);
```

- 生长阶段（0–120s）视作春天，`p` 从 0.02 缓慢到 0.25（夏初）。
- 120s 后从夏初开始正常四季循环；每季 `SEASON_SECONDS = 20s`，一年 80s。
- `storyYear(t)`：`t<120` 为第 1 年；之后每跨过 80s 进入下一年，第 2 年从 180s 开始。

### 1.3 当前常量

```js
SEASON_SECONDS = 20;
GROW_END = 120;
GROW_END_P = 0.25;
STORY_END = 120 + (1 - 0.25) * 80 + 80 - 0.1; // 259.9 秒
```

播放器显示时四舍五入为 **04:20**。

## 2. 14 章章节表（唯一权威）

源码：`src/main.js` 的 `CHAPTERS` 数组。章节起止时间必须与视觉事件对齐，改章节时间时请同时检查 `GROW_KEYS`、`CAM_KEYS`、`RAIN_WINDOWS`、种子时间、雪/叶/果实的 `p` 窗口。

| # | 起止（秒） | 标题 | 画面应看到 |
|---|---|---:|---|
| 1 | 0–16 | 种子入土 | 种子从上方落进土里，微距；种子不要大 |
| 2 | 16–32 | 春雨滋润 | **16–31 秒下雨**；种子吸水膨胀、种皮裂开 |
| 3 | 32–56 | 向下扎根 | 主根向下、侧根和板根铺开；种子继续裂壳 |
| 4 | 56–76 | 破土发芽 | 主干开始抽长，子叶展开；62–72 秒有雨 |
| 5 | 76–94 | 幼苗初长 | 主干长高、早期叶片出现；子叶逐渐退场 |
| 6 | 94–108 | 小树成形 | 一级侧枝开始生长，树冠展开 |
| 7 | 108–120 | 长成大树 | 多级枝条补齐，树冠接近完整 |
| 8 | 120–140 | 第一年 · 夏 | 树冠浓绿；树已完成 |
| 9 | 140–160 | 第一年 · 秋 | 秋叶、落叶、地面落叶层 |
| 10 | 160–180 | 第一年 · 冬 | 下雪、枝头积雪、草退场 |
| 11 | 180–200 | 第二年 · 春 | 新叶、春花（小花实例） |
| 12 | 200–220 | 第二年 · 夏 | 满树、树荫 |
| 13 | 220–240 | 第二年 · 秋 | 果实由小到大，成熟后掉落 |
| 14 | 240–260 | 第二年 · 冬 | 雪景收尾，故事结束（实际停在 259.9s） |

## 3. 生长阶段与枝条/根系时间

### 3.1 枝条

`buildTree()` 中：

```js
MAX_DEPTH = 4;
DUR = [0.24, 0.16, 0.12, 0.08, 0.05];
```

- 主干 `gStart = 0.06`，`g1 = 0.06 + 0.24 = 0.30`；
- 一级枝从 `g = 0.30` 开始，持续 `0.16`；依次到末级枝；
- 因此：
  - `g=0.30` 约在 96s：一级枝出现（第 6 章）
  - `g=0.46` 左右：一级枝完成、二级枝展开
  - `g=0.58` 左右：三级枝
  - `g=0.71` 左右：末级枝；最后在 120s 全树完成

实际 `g` 由 `GROW_KEYS` 平滑映射，`g=0.30` 大约对应 95–96s。

### 3.2 根系

`rootChain()` 当前：

```js
dur = [0.025, 0.020, 0.015, 0.010]
```

主根 `gStart = 0.012` → `g1≈0.037`（约 40–45s 内完成主体）；侧根从主根 `g1` 附近开始，板根 `gStart=0.045`。因此第 3 章 32–56s 内能看到主根和早期侧根；第 4–5 章根系继续加粗/扩展。

> 若只改 `GROW_KEYS`，要重新用 `docs/07` 的核对清单检查第 3 章是否还有“只有一根主根”的空白。

## 4. 镜头脚本

源码：`CAM_KEYS` + `cameraFrameAt(t)`。

```js
[
  [0, 0.10, 0.9],
  [18, 0.08, 1.1],
  [32, 0.00, 1.3],
  [42, -0.55, 2.7],
  [56, -0.70, 3.1],
  [70, 0.00, 1.8],
  [76, 0.35, 2.2],
  [94, 1.20, 3.8],
  [108, 2.20, 5.2],
  [120, 3.00, 10.8],
]
```

每项 `[t, targetY, viewH]`：`targetY` 是相机看向的 y，`viewH` 是希望框住的垂直高度；`fitR = viewH / (2 * tan(fov/2))`。

- 0–32s：种子微距；
- 32–56s：根系剖面（targetY 变负）；
- 56–76s：破土/子叶；
- 76–94s：幼苗；
- 94–108s：小树；
- 108–120s：后拉到全树；
- 之后 `cameraFrameAt` 返回 `null`，改由 `crownTop + BOTTOM_Y` 自动框全树。

`BOTTOM_Y = -0.62 - 3.6 * smoothstep(0, 0.34, g)`，长成后框到较深根系。

## 5. 播放器和时间控制

源码：状态区（`CHAPTERS` 下方）与 `animate()` 开头。

- `storyTime` 是唯一时间基准；`playing` 为布尔。
- 播放时 `storyTime += realDt`（真实时间，限制最大 0.1s，避免切后台跳跃）。
- 到 `STORY_END` 自动 `playing=false`，不循环。
- `?freeze`：`t = FREEZE_T`，`playing=false`，播放器隐藏。
- `?video`：`t = videoT`，由 `tools/render.js` 或其它外部脚本喂入。
- `?t0=N`：初始 `storyTime=N`，默认继续播放。

进度条和章节刻度：

- `#timeline` 的 `min/max` 由 `STORY_END` 设置；
- `#marks` 由 `CHAPTERS` 的 `start` 自动生成；
- `updateChapterUI(t)` 按 `start` 找当前章节，更新 `#chapterIndex/#chapterTitle/#chapterText`；
- `syncPlayer()` 更新 `#timecode`、滑块位置、进度色、播放图标。

## 6. 改时间轴的标准流程

1. 改 `GROW_KEYS`（决定 `g` 相对时间）；
2. 改 `CHAPTERS` 的 `start/end` 与文案；
3. 改 `CAM_KEYS` 的对应时间；
4. 改种子时间（`seedSwell/seedSplit/seedFade/seedPlant` 在 `animate()` 内）；
5. 改 `RAIN_WINDOWS`；
6. 检查 `snowA`、`winterF`、`groundLeafDecay`、`fruitGrow/fruitFall` 的 `p` 窗口是否仍在对应章节；
7. 改 `README.md` 的章节表和总时长；
8. 用 `?t0=16`、`?t0=20`、`?t0=32/56/76/94/108/120` 逐章截图核对。

## 7. 已知教训

- 曾出现“第 2 章春雨滋润开始时雨已经下完”：因为雨窗写成 4–15s，而章节从 16s 才开始。**章节时间和视觉窗口必须来自同一张表**。
- 曾出现“第 3 章向下扎根时侧根还没出现”：根系的 `dur` 与 `GROW_KEYS` 不同步。改根参数后务必看第 3 章实际截图。
- `storySeason` 的 `p` 是“故事季节”，不是自然季节；生长阶段故意固定在春季，不要用真实年份公式替代。
