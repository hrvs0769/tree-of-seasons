## 1. 视觉目标

“一棵树的四季”不是写实植物图鉴，也不是低幼卡通，而是：

> **安静、自然、有体积感、适合投影的课堂自然观察片。**

关键词：

- **自然**：树皮有纹理，根有分叉和细根并一直扎到含水层，土层有颗粒与不均匀的界线，山有远近层次，天上有云和偶尔飞过的鸟。
- **体积感**：光从侧面来，树干有暗部与受光面，土壤有凹坑、团粒、阴影，不是平面贴图。
- **克制**：不堆特效、不加大饱和色块、不做喧闹的游戏化 UI。
- **课堂友好**：文字和按钮离树远，最后一排看得清，老师站在讲台上能操作。
- **可解释**：孩子能看出「种子 / 根 / 树干 / 树枝 / 叶 / 花 / 果 / 小鸟 / 昆虫」，细节服务于认知，不为了炫技。
- **文字与画面同源**（第二轮强化）：旁白提到的元素（春雨、裂壳、树荫、小鸟、昆虫、果实、雪、新的轮回）画面里都要有；季节标签与配色不能错位。
- **可复现**（第二轮新增硬约束）：同一 `?t0=N&freeze` 两次独立加载必须逐像素一致，否则所有截图审查没有意义。

## 2. 评分维度（每项 1–5 分）

第二轮把八维扩展为**十维**，新增「确定性 / 可复现」与「文案—画面对齐」两项：

| 维度 | 1 分 | 3 分 | 5 分 | 权重 |
|---|---|---|---|---|
| 构图与镜头 | 主体被裁切/遮挡 | 主体完整但构图普通 | 主体明确、前后景有层次，近景/全景切换自然 | 12% |
| 光照与曝光 | 死黑/过曝 | 能看清但平 | 逆光有轮廓光，暗部有细节，季节光感一致 | 12% |
| 树体细节 | 塑料棍/规则几何 | 能看出枝干结构 | 树干有锥度与弯曲，枝条分叉自然，树皮有纹理 | 15% |
| 根系细节 | 一根直锥或稀疏线条 | 主根+侧根可见 | 主根粗壮、侧根分层、细根/根毛自然，深扎到含水层 | 12% |
| 土壤与地形 | 平整色块/水平直线 | 有颜色和颗粒 | 6 层起伏层界、透镜体/裂缝/团粒/石子/孔隙，近景有体积 | 12% |
| 远景与季节 | 平贴的灰带 | 有远山但层次少 | 远中近三层山脊、真实可见的云、空气透视、四季色自然 | 8% |
| UI 与排版 | 小按钮、挤压、老式控件 | 能用但普通 | 控制层级清楚，按钮有尺寸/状态/圆角，投影可读 | 8% |
| 课堂可用性 | 控件挡树/看不清 | 能操作但要点提示 | 字幕/按钮在舞台外，章节/找一找/朗读流程清楚 | 5% |
| **确定性 / 可复现** | 每次加载画面都不同 | 定帧大致稳定 | `?t0=N&freeze` 逐像素一致，拖拽/暂停/合影也不漂移 | 8% |
| **文案—画面对齐** | 旁白说的画面里没有 | 大部分对齐 | 14 章逐章可核对，季节标签与配色、物候顺序完全一致 | 8% |

**通过线**：平均分 ≥ 4.0，且树体、根系、土壤、UI 四项都不能低于 3 分；另外「确定性 / 可复现」为第二轮硬门槛——`ImageChops.difference` 的 `bbox` 必须为 `None`，否则本轮不得标记完成。

## 3. 模块标准

### 3.1 树体

- 主干从根颈向上有自然锥度和轻微 S 弯，不是直圆柱。
- 一级侧枝从主干不同高度发出，角度不完全对称；末级枝有收尖。
- 树皮使用竖向纹理 + bump，近景有粗糙感；树冠边缘不是规则球形。
- 树干与树冠的比例：生长阶段尊重 `GROW_KEYS`，不要突然变成成年大树。
- 禁止：所有枝条同角度、同粗细、像铁丝网；树干像塑料管。

### 3.2 根系

- 主根向下有连续锥度和弯曲，侧根沿主根不同高度分出，板根贴地铺开。
- 根部必须有**分叉层级**，末梢逐渐变细；在大树阶段要有足够的细根量。
- **第 2 年继续深扎到含水层**（`rootAge`），水面反光/波纹/气泡/根尖光点随根抵达而亮起。
- 根与土壤不是「插在平面上的棍子」：根颈处有根盘，根周围有暗部和细土颗粒；根系有 z 体积。
- 禁止：单根直锥、所有根同色同粗细、根系只在土表、根跟着树冠一起摇。

### 3.3 土壤剖面

- **6 层**（表土 / 心土 / 底土 / 毛管湿润带 / 含水饱和带 / 母质）之间有**起伏的层界**，不能是一条水平直线。
- 层界用 4 八度噪声/透镜体/侵蚀袋状结构打破，局部有土层混合；贴图 `repeat(1,1)` 不得出现纵向接缝。
- 有 3D 团粒、石子、草根、裂缝、孔隙、有机质斑块、潜育斑与渗流纹；近景有暗部和湿润/干燥差异；第一章微距不能是一块黑板。
- 禁止：四条完全平行的色带、贴图重复感、只有一张平面图没有体积。

### 3.4 远景与天空

- 至少三层：远山、中景丘陵、近景草坡；远山颜色更冷、更接近雾。
- 远山有山脊线和雪线，雪线随季节不完全消失。
- **云必须真的可见**（`lo = 0.40 - cloudCover*0.14`），且随季节/雨量变化；天空里要有偶尔飞过的鸟群、云影、飞絮。
- 山体底部与雾/地面自然衔接，不能出现「剪纸边缘」或一条水平切线。

### 3.5 UI

- 主按钮 ≥ 44px（课堂模式 ≥ 54px），文字和图标有明确层级。
- 控件使用统一的圆角、边框、hover/focus 状态；不使用默认浏览器按钮外观。
- 课堂模式：字幕、控制条在 3D 舞台之外，不遮挡树；季节转盘指针与色象限对齐。
- 禁止：小字号密铺、按钮像旧网页、控件互相挤压、文字压在画面上。

## 4. 自动审查流程

### 4.1 生成标准截图

```bash
cd /Users/liuhuirong/WorkBuddy/Claw/tree-of-seasons
./tools/visual-audit.sh audit-rN                     # 快速模式：1280×800，8 张
AUDIT_FULL=1 ./tools/visual-audit.sh audit-rN        # 全量模式：1440×900，24 张
```

脚本会：

1. 用 esbuild 重新构建 `app.js`（改完 `src/main.js` 必须重建，见 `docs/06`）；
2. **快速模式（默认 1280×800）共 8 张**：`desktop-06-seed / desktop-20-rain / desktop-44-root / desktop-100-sapling / desktop-210-birds / desktop-230-fruit / desktop-250-water / class-210-ui`；必留 `t=6 / 44 / 210 / 250`，夏/秋/冬/第二年春放到全量模式；
3. **全量模式（`AUDIT_FULL=1`，1440×900）共 24 张**：20 张桌面关键帧（6 / 20 / 44 / 66 / 100 / 108 / 120 / 128 / 140 / 150 / 160 / 170 / 190 / 200 / 210 / 220 / 230 / 240 / 250 / 260）+ 2 张课堂 UI（`class-128-ui` / `class-210-ui`）+ 2 张 390×844 手机 UI（`mobile-128-ui` / `mobile-210-ui`）；
4. 两份 `ITEMS` 的条目数必须与 **8 / 24** 一致，改清单时同步改注释；
5. 生成该轮目录下的 `sheet.png` 拼图、`metrics.json`（亮度/对比度/边缘密度）和 `report.md` 评分骨架。

> 所有截图都用 `?stage&t0=N&freeze` 或 `?class&t0=N&freeze`：固定树种子 + `dt=0` + 只重绘一次（`staticKey`），软件渲染的无头截图不会卡死。`shots/` 被 `.gitignore` 忽略，属本机视觉迭代产物，不进仓库、不部署。仓库里保留的是**标准、脚本和每轮结论**（本文第 5–7 节），截图可随时用脚本复现。

### 4.2 视觉识别与评分

1. 用图片查看工具读取 `sheet.png`，必要时逐张读原图；
2. 对照第 2 节的十个维度打分，记录在 `report.md`；
3. 每轮只列**最影响观感的 3 个问题**，按「确定性 > 文案对齐 > 树体 > 根系 > 土壤 > 远景 > UI」的优先级修复；
4. 修复后重新生成同一组截图，比较前后差异，保留退步项；
5. 通过线以下不得标记为完成；`bbox != None` 直接判不通过。

### 4.3 报告模板

每轮报告至少包含：

```text

```
