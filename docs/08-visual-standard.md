> 最后更新：2026-11-06 · 对应代码：`349d91f`（课堂模式 · 找一找队列 · 远山改版 · 视觉审查 r1）

## 1. 视觉目标

“一棵树的四季”不是写实植物图鉴，也不是低幼卡通，而是：

> **安静、自然、有体积感、适合投影的课堂自然观察片。**

关键词：

- **自然**：树皮有纹理，根有分叉和细根，土层有颗粒与不均匀的界线，山有远近层次。
- **体积感**：光从侧面来，树干有暗部与受光面，土壤有凹坑、团粒、阴影，不是平面贴图。
- **克制**：不堆特效、不加大饱和色块、不做喧闹的游戏化 UI。
- **课堂友好**：文字和按钮离树远，最后一排看得清，老师站在讲台上能操作。
- **可解释**：孩子能看出“种子 / 根 / 树干 / 树枝 / 叶 / 花 / 果”，细节服务于认知，不为了炫技。

## 2. 评分维度（每项 1–5 分）

| 维度 | 1 分 | 3 分 | 5 分 | 权重 |
|---|---|---|---|---|
| 构图与镜头 | 主体被裁切/遮挡 | 主体完整但构图普通 | 主体明确、前后景有层次，近景/全景切换自然 | 15% |
| 光照与曝光 | 死黑/过曝 | 能看清但平 | 逆光有轮廓光，暗部有细节，季节光感一致 | 15% |
| 树体细节 | 塑料棍/规则几何 | 能看出枝干结构 | 树干有锥度与弯曲，枝条分叉自然，树皮有纹理 | 20% |
| 根系细节 | 一根直锥或稀疏线条 | 主根+侧根可见 | 主根粗壮、侧根分层、细根/根毛自然，和土壤有接触感 | 15% |
| 土壤与地形 | 平整色块/水平直线 | 有颜色和颗粒 | 层界起伏、有透镜体/裂缝/团粒/石子，近景有体积 | 15% |
| 远景与季节 | 平贴的灰带 | 有远山但层次少 | 远中近三层山脊、空气透视、雪线/季节色自然 | 5% |
| UI 与排版 | 小按钮、挤压、老式控件 | 能用但普通 | 控制层级清楚，按钮有尺寸/状态/圆角，投影可读 | 10% |
| 课堂可用性 | 控件挡树/看不清 | 能操作但要点提示 | 字幕/按钮在舞台外，章节/找一找/朗读流程清楚 | 5% |

**通过线**：平均分 ≥ 4.0，且树体、根系、土壤、UI 四项都不能低于 3 分。

## 3. 模块标准

### 3.1 树体

- 主干从根颈向上有自然锥度和轻微 S 弯，不是直圆柱。
- 一级侧枝从主干不同高度发出，角度不完全对称；末级枝有收尖。
- 树皮使用竖向纹理 + bump，近景有粗糙感；树冠边缘不是规则球形。
- 树干与树冠的比例：生长阶段尊重 `GROW_KEYS`，不要突然变成成年大树。
- 禁止：所有枝条同角度、同粗细、像铁丝网；树干像塑料管。

### 3.2 根系

- 主根向下有连续锥度和弯曲，侧根沿主根不同高度分出，板根贴地铺开。
- 根部必须有**分叉层级**，末梢逐渐变细；在大树阶段要有足够的细根量。
- 根与土壤不是“插在平面上的棍子”：根颈处有根盘，根周围有暗部和细土颗粒。
- 禁止：单根直锥、所有根同色同粗细、根系只在土表。

### 3.3 土壤剖面

- 表土、心土、底土、母质层之间有**起伏的层界**，不能是一条水平直线。
- 层界可用噪声/透镜体/侵蚀袋状结构打破，局部有土层混合。
- 有 3D 团粒、石子、裂缝、有机质斑块；近景有暗部和湿润/干燥差异。
- 禁止：四条完全平行的色带、贴图重复感、只有一张平面图没有体积。

### 3.4 远景

- 至少三层：远山、中景丘陵、近景草坡；远山颜色更冷、更接近雾。
- 远山有山脊线和雪线，雪线随季节不完全消失。
- 山体底部与雾/地面自然衔接，不能出现“剪纸边缘”或一条水平切线。

### 3.5 UI

- 主按钮 ≥ 44px（课堂模式 ≥ 54px），文字和图标有明确层级。
- 控件使用统一的圆角、边框、hover/focus 状态；不使用默认浏览器按钮外观。
- 课堂模式：字幕、控制条在 3D 舞台之外，不遮挡树。
- 禁止：小字号密铺、按钮像旧网页、控件互相挤压、文字压在画面上。

## 4. 自动审查流程

### 4.1 生成标准截图

```bash
cd /Users/liuhuirong/WorkBuddy/Claw/tree-of-seasons
./tools/visual-audit.sh audit-r1
```

脚本会：

1. 用 esbuild 重新构建 `app.js`；
2. **快速模式**（默认）：1280×800 截 6 个场景时间点（种子 / 根 / 幼苗 / 夏 / 冬 / 春）+ 1 张课堂 UI；
3. **全量模式**（`AUDIT_FULL=1 ./tools/visual-audit.sh audit-rN`）：1440×900 截 10 个场景时间点（种子 / 春雨 / 根系 / 破土 / 幼苗 / 夏 / 秋 / 冬 / 春 / 果）+ 2 张课堂 UI + 1 张 390×844 手机；
4. 生成该轮目录下的 `sheet.png` 拼图、`metrics.json`（亮度/对比度/边缘密度）和 `report.md` 评分骨架。

> `shots/` 被 `.gitignore` 忽略，属于本机视觉迭代产物，不进仓库、不部署。仓库里保留的是**标准、脚本和每轮结论**（本文第 6 节），截图可随时用脚本复现。

### 4.2 视觉识别与评分

1. 用图片查看工具读取 `sheet.png`，必要时逐张读原图；
2. 对照第 2 节的八个维度打分，记录在 `report.md`；
3. 每轮只列**最影响观感的 3 个问题**，按“树体 > 根系 > 土壤 > 远景 > UI”的优先级修复；
4. 修复后重新生成同一组截图，比较前后差异，保留退步项；
5. 通过线以下不得标记为完成。

### 4.3 报告模板

每轮报告至少包含：

```text
轮次 / 日期 / 代码版本：
截图尺寸与时间点：
八维评分（1-5）：
平均分：
最影响观感的 3 个问题：
本轮改动：
下一轮：
```
